# QBI / CryoSight

QBI is a cryo-electron tomography project for the CZII CryoET Object
Identification dataset. It combines:

- a local CryoSight web viewer in `frontend/` for loading Zarr tomograms,
  inspecting orthogonal slices, overlaying pick labels, running optional model
  inference, and reviewing detections;
- a PyTorch segmentation backend in `backend/` for training, segmentation, and
  optional localization;
- helper scripts for rendering Zarr cross-sections and converting predictions
  into CZII pick JSON files.

The frontend is intentionally lightweight: `frontend/server.js` is a plain
Node.js HTTP server and the browser app is vanilla HTML, CSS, and JavaScript.
The backend is a Python package built around PyTorch, copick, OME-Zarr, and a
YAML-driven training/inference pipeline.

## Dataset

The project targets the Kaggle CZII CryoET Object Identification dataset:

```text
https://www.kaggle.com/competitions/czii-cryo-et-object-identification/data
```

The frontend sample-data scanner expects a Kaggle-like tree such as:

```text
frontend/sample_data/
  cryo_object detection/
    train/
      static/
        ExperimentRuns/
          TS_5_4/
            VoxelSpacing10.000/
              denoised.zarr/
      overlay/
        ExperimentRuns/
          TS_5_4/
            Picks/
              apo-ferritin.json
              beta-amylase.json
              beta-galactosidase.json
              ribosome.json
              thyroglobulin.json
              virus-like-particle.json
```

Each `.zarr` directory stores a multiscale 3D tomogram. `Picks/*.json` files
store particle annotations in CZII pick format with physical coordinates in
Angstroms. CryoSight aligns those picks to voxel space using Zarr metadata or
the `VoxelSpacing10.000` path convention.

Supported molecule classes:

- `apo-ferritin`
- `beta-amylase`
- `beta-galactosidase`
- `ribosome`
- `thyroglobulin`
- `virus-like-particle`

`beta-amylase` is treated as an unscored decoy/calibration class in analysis
text, matching the CZII competition context.

## Requirements

- Node.js 18 or newer for the web viewer.
- Python 3.9 or newer for the backend package.
- Python 3 with `zarr`, `numpy`, and `Pillow` for frontend slice rendering
  helpers.
- PyTorch and the backend Python dependencies for training and inference.
- Optional: 3D Slicer for NRRD export/open workflows.
- Optional: an Anthropic API key for AI-generated dataset analysis in the
  frontend server.
- Optional: a trained checkpoint for frontend-triggered inference.

## Setup

Install frontend dependencies:

```bash
cd frontend
npm install
```

Install lightweight Python packages used by frontend Zarr helpers:

```bash
python3 -m pip install zarr numpy pillow
```

Install backend dependencies in your preferred Python environment:

```bash
cd backend
python3 -m pip install -e .
```

For Kaggle or GPU training, install the additional runtime packages expected by
the backend if your environment does not already include them:

```bash
python3 -m pip install torch copick copick-utils ome-zarr tensorboard
```

## Running the Frontend

Start the local web server:

```bash
cd frontend
npm start
```

Then open:

```text
http://localhost:3000
```

Use a different port with:

```bash
cd frontend
PORT=3015 npm start
```

The server serves `frontend/index.html`, static assets, Zarr APIs, upload APIs,
slice rendering APIs, optional 3D Slicer export routes, optional inference
routes, and optional dataset analysis routes.

## Frontend Capabilities

CryoSight supports one local review workflow:

1. Load a `.zarr` tomogram from `frontend/sample_data/`, a browser folder
   upload, or a local filesystem path registered through the UI.
2. Discover multiscale Zarr levels and per-level shapes.
3. Render interactive X, Y, and Z orthogonal slice views.
4. Overlay curated CZII `Picks/*.json` labels or uploaded labels.
5. Optionally run model inference through the backend direct-inference script.
6. Convert model predictions into pick-style detections.
7. Review molecule counts, positions, confidence, and analysis text.

Browser folder uploads can omit hidden Zarr metadata files such as `.zarray`,
`.zattrs`, and `.zgroup`. If uploaded Zarr metadata is missing, use the local
path field instead so the server can read the original folder directly.

## Frontend API Summary

| Route | Purpose |
| --- | --- |
| `GET /api/scans` | List sample, uploaded, and registered local Zarr scans. |
| `POST /api/local-zarr` | Register an existing local `.zarr` path. |
| `GET /api/zarr/metadata` | Return raw Zarr multiscale metadata. |
| `GET /api/zarr/preview` | Return level shapes, loaded picks, and initial analysis data. |
| `GET /api/zarr/slice` | Return one contrast-windowed grayscale slice as raw bytes. |
| `POST /api/upload-zarr` | Upload a Zarr folder into `uploaded_scans/`. |
| `POST /api/upload-picks` | Upload pick JSON labels for the selected scan. |
| `GET /api/slicer/export` | Export a selected Zarr level as NRRD. |
| `POST /api/slicer/open` | Export and open in 3D Slicer when available. |
| `POST /api/inference/run` | Start trained-model inference for a selected scan. |
| `GET /api/inference/progress` | Stream inference progress and completion events. |
| `POST /api/analysis` | Generate or return structured pick analysis. |

## Model Inference From the Frontend

The frontend server can launch:

```text
backend/inference/run_inference_direct.py
```

The current server expects a checkpoint at:

```text
~/Downloads/czii-weights/weight_best.ckpt
```

It writes generated model output under:

```text
frontend/predictions/
```

Device selection is automatic in `frontend/server.js`:

- Apple Silicon macOS: `mps`
- non-macOS: `cuda`
- fallback macOS Intel: `cpu`

Progress is streamed to the browser over Server-Sent Events. The inference
script is expected to emit progress lines like:

```text
__QBI_PROGRESS__:<fraction>:<batch>/<total>:<bar>
```

## Backend Pipeline

The backend is a PyTorch-native 3D segmentation pipeline with:

- 3D U-Net, residual U-Net, and attention U-Net variants;
- class-balanced patch sampling;
- Torch-native 3D augmentation;
- CE + Tversky loss support;
- sliding-window segmentation inference;
- optional probability scoremaps;
- optional connected-component localization.

Run the full backend pipeline on Kaggle-style inputs:

```bash
cd backend
python scripts/run_all.py --config configs/default.yaml \
  --input-root /kaggle/input/competitions/czii-cryo-et-object-identification \
  --output-root /kaggle/working
```

Or run stages individually:

```bash
cd backend
python scripts/setup_copick.py \
  --input-root /kaggle/input/competitions/czii-cryo-et-object-identification \
  --output-root /kaggle/working

python scripts/build_targets.py --config configs/default.yaml
python scripts/train_model.py --config configs/default.yaml
python scripts/segment.py --config configs/default.yaml \
  --weights /kaggle/working/train_results/net_weights_BEST.pt \
  --write-scoremap
```

See `backend/README.md` for backend architecture, configuration notes, class
mapping, and output details.

## Helper Scripts

Render a labeled Zarr cross-section:

```bash
cd frontend
python3 render_zarr_cross_section.py \
  --zarr "sample_data/cryo_object detection/train/static/ExperimentRuns/TS_5_4/VoxelSpacing10.000/denoised.zarr" \
  --picks "sample_data/cryo_object detection/train/overlay/ExperimentRuns/TS_5_4/Picks" \
  --level 1 \
  --axis z \
  --slice 45 \
  --labels \
  --marker-outline \
  --output ts_5_4_level1_z45_overlay.png
```

Convert model predictions into per-class CZII pick files:

```bash
cd frontend
python3 format_predictions_to_picks.py \
  --predictions predictions/predictions_TS_5_4.json \
  --output-root predictions/formatted_picks \
  --overwrite
```

## Optional Environment

`frontend/server.js` reads `frontend/.env` on startup. For AI-generated
dataset analysis:

```bash
ANTHROPIC_API_KEY=your_key_here
ANTHROPIC_MODEL=claude-sonnet-4-6
```

Without an API key, the app still returns deterministic local analysis.

## Troubleshooting

If uploaded Zarr metadata is missing, use the local path loader. Browser folder
upload can skip hidden dotfiles required by Zarr.

If slices fail to render, confirm the helper imports work:

```bash
python3 -c "import zarr, numpy, PIL"
```

If frontend inference fails with a missing checkpoint, place the trained file
at `~/Downloads/czii-weights/weight_best.ckpt` or update the checkpoint path in
`frontend/server.js`.

If frontend inference fails with a missing script, confirm the repository root
contains `backend/inference/run_inference_direct.py`.

If 3D Slicer open/export fails, use the NRRD export route first and open the
exported file manually in Slicer.

## Development Notes

- Keep large raw datasets and generated outputs out of commits.
- The server is designed for local research workflows and does not implement
  production authentication, quotas, or hardened upload handling.
- The frontend assumes Zarr arrays are readable as local filesystem folders.
